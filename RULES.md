# Правила вёрстки Radugadesign

Единый свод для всех презентаций студии. Числа, которые читает сборщик,
лежат в `rdp/dna.yaml`; здесь — смысл и порядок работы. Правило, которое
есть только в тексте и не перенесено в сборщик, не работает: всё, что можно,
зашито в код.

## 1. Работа с живым файлом

- Формат — Google Презентации, правки — только через Slides API точечно.
  Никаких «выгрузить pptx → поправить → залить обратно»: перезалив стирает
  правки, которые люди сделали руками.
- **Сборщик создаёт новый файл один раз — при первой сборке.** Всё дальше
  (добавить, удалить, слить слайды, поменять текст или картинку) делается
  в том же файле: `createSlide`, `deleteObject`, `replaceAllText`,
  `replaceImage`. Новый файл = потеря ручных правок и мёртвая ссылка у клиента.
- **Перед каждой правкой — прочитать презентацию** (`presentations.get`).
  База для правки — то, что лежит в файле сейчас, а не память о нём.
  Любое расхождение с манифестом — ручная правка человека, она главнее.
  Манифест догоняет дек, не наоборот.
- Если текст в поле выглядит оборванным — человек прямо сейчас его печатает.
  В это поле не писать, нужный текст отдать в чат.
- Массовые правки отбирать по устойчивому признаку элемента (подстрока
  текста, `objectId`, архетип), а не по длине текста или координате.
  Копирайт — самый длинный текст на слайде, фильтр «длиннее N» его утащит.
- После любой правки — рендер затронутых слайдов (`pages.getThumbnail`)
  и проверка глазами.

## 2. Шрифты и цвета

- Шрифт — **Inter**. Заголовки — Inter Medium, тело — Inter.
- Фон контент-слайдов тёмный.
- Заголовки — белый `#ffffff`. Тело — `#e7e7e7`. Акцент внутри текста
  (подзаголовок, ключевая фраза) — белым.
- Заголовок слайда — 20 pt, top-left от общего левого поля.
- Внутренний текст контент-слайдов — 11 pt, и мини-заголовок, и тело;
  иерархия держится жирностью, не размером.
- Служебное — номер страницы и вертикальный копирайт справа — мелко,
  размеры зашиты в сборщик.

## 3. Сетка и хром

- Формат 16:9, 10″ × 5.625″.
- Единое левое поле — от него стартуют заголовок, тело и подписи. Не ломать.
- На каждом контент-слайде: заголовок top-left, номер страницы в белом
  кружке по центру низа, вертикальный копирайт по правому краю.
- **Номер страницы = физическая позиция слайда.** После любого изменения
  состава дека перечитать его и проставить номера заново.
- **Заголовок контент-слайда — один формат на весь дек: «Название ● раздел».**
  Название и ● белые, раздел после ● серый (`secondary`), с маленькой буквы:
  «"Rainbow Rain" ● путь гостя». Если раздела нет — просто «Название», без ●.
  Кружка в начале заголовка не бывает, тире вместо ● не ставится. Формат
  одинаков для всех архетипов: сборщик проводит любой заголовок через один
  путь и сам красит текст после ● в серый, ведущий ● отбрасывает.
- Разворот концепции на полноэкранной картинке (`case_hero`) — только
  название, без ●; вторая строка мелко — перевод или пояснение.

## 4. Обложка и финал

- Обложка и финальный слайд — закреплённые шаблоны, их стиль не меняется.
- **Фон обложки и финала — одна и та же картинка, всегда размытая.**
  По умолчанию берётся из набора `assets/covers/` (сеты `01-pastel`,
  `02-blue`, `03-green`, `05-magenta`; `04-red` по умолчанию не брать).
  Цвет сета выбирается под проект. Свой кадр перед вставкой размыть
  (Gaussian ~14 px на 1600 px ширины) и подтянуть яркость и контраст.
- Кадр выбирать по читаемости: верх-слева тёмный (там белый заголовок),
  правый низ тёмный (там лого).
- Обложка: крупно сверху только короткое имя проекта. Подпись-пояснение
  («Концепция … ● площадка») — внизу над датой, 11.2 pt, серым `#999999`.
  Внизу пилюли: дата `ДД.ММ.ГГ` и `radugadesign.com`, справа лого.
- Финал: слоган «be raduga. think design.» — точки после обеих фраз всегда;
  контакты `radugadesign.com` и `hello@radugadesign.com`, лого.
- Полноэкранные фоны не скругляются.

## 5. Картинки

- **Скругление у всех картинок** одинаковое (~0.11″). Slides API скруглять
  не умеет, поэтому скругление запекается в PNG сглаженной маской, 400 ppi.
  Сборщик делает это сам. Перезапекать всегда из исходника.
- **Видео-референсы ставятся гифкой со скруглёнными углами.** Ролик
  (Pinterest, YouTube) режется до 8–12 с, переводится в GIF (~480 px, 10–12
  fps, ≤12 МБ). Углы запекаются в каждый кадр цветом фона слайда (`#212121`)
  со сглаженной маской под фактический размер на слайде — так край мягкий,
  прозрачность не нужна. Гифка с прямыми углами — брак.
- Настоящее видео (mp4) в Slides скруглить нельзя — поэтому видео-референсы
  в дек идут гифками, а не видеоэлементом.
- **Аспект неприкосновенен.** Картинка ставится в родной пропорции, без
  обрезки; бокс подстраивается под картинку. Обрезка разрешена только
  полноэкранному фону.
- **Каждая картинка — отдельный элемент.** Никаких склеенных коллажей:
  человек должен иметь возможность переставлять картинки руками.
- Эскизы со сканов обрезать по краске (убрать пустые поля), иначе рисунок
  выглядит вдвое мельче.

## 6. Композиция

- Композиция — под набор картинок, а не под архетип.
  - Однотипные кадры (серия одной съёмки, стоп-кадры видео) — ровный ряд
    одной высоты.
  - Смешанные референсы — один крупный якорь (45–60 % свободной зоны) и
    2–4 спутника разного масштаба, наложения краями 3–8 %, крупные под
    мелкими, без выравнивания в линию. Вылет за край слайда допустим.
- **Воздух важнее количества.** Рядом с текстом — не больше 3–4 картинок.
  Картинки занимают до ~55 % свободной зоны. «Добавь фоток» — значит
  сильнее отобрать кадры или дать отдельный слайд-галерею, а не утрамбовать.
- Картинка не заходит на текст и не перекрывает другие картинки — проверять
  рендером: смотреть не только «ничего не налезло», но и «не тесно ли».
- Вариант решения держать одним слайдом (`setup`): эскиз-якорь, описание,
  ряд референсов снизу. Пара «кейс + мудборд» размазывает идею на два слайда.

## 7. Текст

- Короткие блоки. В `spec` тело блока длиннее ~170 знаков налезает на
  следующий подзаголовок.
- Названия вариантов и концепций — в кавычках, в стиле кавычек дека.
- Без риторики «не X, а Y», без воды: каждое предложение несёт смысл.

## 8. Перед сдачей

- Рендер каждого слайда и проверка глазами: углы картинок (на увеличенном
  кропе — на общем виде мелкий радиус кажется скруглённым), наложения,
  плотность, читаемость обложки и финала, номера страниц.
- Ссылка на дек — одна. Повторная сборка в новый файл — только по прямой
  просьбе («сделай новую версию отдельным файлом»).
