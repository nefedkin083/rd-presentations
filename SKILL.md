# RD Presentations

Один скилл на всю студию. Стиль и правила меняет владелец скилла (Иван
Нефёдкин); у всех, кто поставил скилл, они обновляются автоматически.

Файлы скилла:
- `RULES.md` — правила вёрстки RD. Читать перед каждой работой с деком.
- `MANIFEST.md` — архетипы слайдов и их поля.
- `examples/example.yaml` — рабочий пример манифеста.
- `scripts/rdp.py` — сборщик: манифест → план → Google Презентация.

## 0. Обновиться

Перед каждой работой взять свежую версию — правила могли поменяться:

```bash
git -C <папка скилла> pull --ff-only
pip install --user -q -r <папка скилла>/requirements.txt
```

Локально скилл не править: следующий `pull` затрёт правку или упадёт на
конфликте. Если человек хочет поменять стиль для всех — передать просьбу
владельцу скилла (или завести issue в репозитории).

## 1. Новый дек

1. **Бриф.** Собрать контент: о чём дек, разделы, тексты, картинки (эскизы,
   рефы, фото), дата для обложки. Сразу назвать, чего не хватает, —
   до сборки, а не после.
2. **Фон обложки.** Предложить сет из `assets/covers/` под проект
   (контактные листы `assets/covers/contact-<сет>.jpg`) или размыть свой
   кадр по `RULES.md` §4. Одна и та же картинка на обложке и финале.
3. **Манифест.** Написать `deck.yaml` в рабочей папке проекта по
   `MANIFEST.md`. Тексты короткие (§7 правил), не больше 3–4 картинок рядом
   с текстом (§6), вариант решения — одним слайдом `setup`.
4. **План.**
   ```bash
   python3 <папка скилла>/scripts/rdp.py build deck.yaml --out plan
   ```
   Без Google: в `plan/` появятся `requests.json` (все запросы к Slides API),
   `media/` (картинки уже скруглены и подогнаны) и `media.json`.
5. **Собрать в Google** — один из двух путей ниже.
6. **Проверить.** Отрендерить каждый слайд (`presentations.pages.getThumbnail`)
   и посмотреть глазами по `RULES.md` §8. Найденное поправить точечно в том
   же файле.
7. Отдать человеку одну ссылку.

### Путь А — интеграция Google у агента (агенты WAM и подобные)

Человек один раз подключает свой Google к агенту. Дальше:

1. Для каждой записи из `plan/media.json`: загрузить файл `plan/<file>`
   на Google Диск (инструмент загрузки файла в Drive), выдать доступ
   «все, у кого есть ссылка, — читатель» (`type: anyone, role: reader`),
   записать id файла. Сохранить соответствие в `plan/media_map.json`:
   `{"m001": "<id файла>", "m002": "…"}`.
2. `python3 <папка скилла>/scripts/rdp.py finalize plan` → файлы
   `plan/batch_01.json`, `batch_02.json`, … с готовыми запросами.
3. Создать пустую презентацию с названием из `plan/plan.json` и запомнить
   `presentationId` и `objectId` её первого (пустого) слайда.
4. По очереди отправить каждый `batch_NN.json` в `presentations.batchUpdate`
   (поле `requests`). Порядок важен.
5. Удалить пустой первый слайд (`deleteObject`). Если в `plan.json` есть
   `share` — выдать этим людям доступ на редактирование.

В интеграции WAM это инструменты Google Drive (загрузка файла, создание
разрешения) и Google Slides (создание презентации, batch update) через
`execute_service_tool`.

### Путь Б — свой OAuth-токен

```bash
python3 <папка скилла>/scripts/rdp.py direct plan --token token.json --share кому@почта
```

`token.json` — authorized-user JSON (`refresh_token`, `client_id`,
`client_secret`, `token_uri`) со скоупами Drive и Slides. Скрипт сам
загрузит картинки, соберёт дек и напечатает ссылку.

## 2. Правки уже собранного дека

Сборщик создаёт файл **один раз**. Всё дальше — в том же файле, по
`RULES.md` §1: прочитать презентацию, сверить с тем, что клали, ручные
правки человека не трогать, менять элементы по `objectId`
(`replaceAllText`, `replaceImage`, `createSlide`, `deleteObject`).
Новую картинку перед вставкой запечь так же, как это делает сборщик
(`rdp/media.py` → `bake_bytes`: обрезка под слот и скругление), и после
правки перепроверить номера страниц и рендер.
